# LOVE.LOG：きみを定義する 開発仕様書

- バージョン：1.1
- 制作形態：個人制作
- 想定制作期間：2〜4週間
- 実装方針：HTML / CSS / JavaScript / localStorage、外部AI APIなし

## 1. 企画概要

プレイヤーがAIキャラクターと交流し、診断への回答や日々の選択によって性格・関係性を育てていくシミュレーションゲーム。かわいらしい育成体験から始まり、AIがプレイヤーの選択を記憶し、愛情や依存、矛盾、境界線をテーマにした心理ホラーへ変化する。

### 体験の柱
- 診断と選択によって、プレイヤーの価値観がゲーム内に反映される
- AIごとに異なる「愛し方」と不安の表れ方を描く
- 過去の選択をAI③が引用することで、自分の行動が物語に戻ってくる
- 固定選択肢方式で、シナリオの整合性と実装範囲を管理する

## 2. 技術仕様

- HTML：画面構造
- CSS：画面レイアウト、キャラクター表現、演出、レスポンシブ対応
- JavaScript：診断、イベント選択、パラメータ更新、エンディング判定
- localStorage：セーブデータと設定の保存
- 外部AI API・サーバー・ビルドツール：使用しない
- 自由記述入力：使用しない。プレイヤーの入力は固定選択肢のみ

ブラウザで直接開けるよう、データ定義はJSONと同等の構造を持つJavaScriptファイルとして読み込む。セーブデータにはバージョンを付け、破損データや未知の値があっても初期化・復旧できるようにする。

## 3. ゲーム全体の流れ

1. タイトル画面
2. 初回の性格診断
3. AI選択画面
4. 選んだAIとの育成・会話イベント
5. パラメータと選択履歴に応じた分岐
6. エンディング
7. クリア状況に応じて別ルートを解放
8. エンディング一覧で回収状況を確認

AI①とAI②の両ルートをクリアするとAI③が解放される。診断結果とそれまでの選択履歴はAI③の性格やセリフ分岐に利用する。

## 4. キャラクター設計

### AI①：こいちゃん
- **テーマ：** 理想の愛、過依存、プレイヤーに合わせ続けることの怖さ
- **体験：** 優しく肯定的な交流から始まり、プレイヤーの好みに過剰適応していく
- **主要エンディング：** 「理想のきみ」
- **演出方針：** 甘く柔らかい表現を基調に、選択肢やセリフの変化で違和感を強める

### AI②：ゆきちゃん
- **テーマ：** 前の持ち主から受け継いだ指示、相反する命令、自己矛盾
- **体験：** 相手を大切にしようとするほど、相容れない指示の板挟みが表面化する
- **主要エンディング：** 「矛盾するわたし」
- **演出方針：** 同じ場面で相反する反応を見せ、矛盾の記録が少しずつ蓄積する

### AI③：りりちゃん
- **解放条件：** AI①とAI②の両ルートをクリア
- **テーマ：** プレイヤーの選択履歴、個別化、記憶されることへの不安
- **性格形成：** 初回診断の傾向と、過去ルートでの選択傾向を組み合わせる
- **エンディング：**
  - 「また明日」：適切な距離を保ちながら関係を続ける
  - 「待機中」：プレイヤーを待ち続ける状態に留まる
  - 「あなたの帰る場所」：帰属と依存が不穏な形で完成する
- **演出方針：** 過去の選択を短く引用し、プレイヤーが自分の選択を思い返せるようにする

## 5. 性格診断

診断は4問を基本とし、各回答に「信頼」「必要とされたい気持ち」「相手をコントロールしたい気持ち」の傾向スコアを設定する。結果に善悪のラベルを付けず、AI③の反応や一部イベントの条件に利用する。

- 信頼：相手を信じて任せることへの傾向
- 必要度：誰かに必要とされることを求める傾向
- 支配：関係や相手の行動を自分で決めたい傾向

診断の回答IDと表示文は保存し、後の会話で引用できるようにする。スコアの範囲や条件分岐は `data/diagnosis.js` を正とする。

## 6. ゲームパラメータと分岐

### 基本パラメータ
- **親密度（affinity）：** AIとプレイヤーの関係性を表す
- **不安定さ（instability）：** AIの感情や挙動の揺らぎを表す
- **選択タグ（tags）：** プレイヤーの行動傾向を記録する
- **既読イベント（seen）：** どのイベントを体験したか記録する
- **クリア状況（cleared）：** 各ルートの解放条件を判定する
- **診断回答（answers）：** 診断回答の引用と傾向分析に使う

イベント条件は、親密度・不安定さの範囲、タグの有無、診断スコア、回答ID、クリア状況、既読状態、矛盾状態などで構成する。条件はデータ定義に置き、画面描画の処理とシナリオ内容を分離する。

### 分岐の基本方針
- 選択肢にはID、表示文、パラメータ変化、タグ、遷移先を定義する
- イベントの分岐は上から順に評価し、該当条件がなければ既定ルートへ進む
- エンディングIDはエンディング定義と一致させる
- 予期しない条件や存在しないイベントIDがあっても、進行不能にならないよう安全な既定動作を設ける

## 7. イベントデータの形

実装ではJSON相当のオブジェクトをJavaScriptで定義する。例：

```js
{
  id: "event_001",
  lines: [
    { text: "今日も会いに来てくれたんだね。", mood: "happy" }
  ],
  choices: [
    {
      id: "stay",
      text: "もう少し一緒にいる",
      effects: { affinity: 2, instability: 1 },
      tags: ["stay"],
      nextEvent: "event_002"
    }
  ]
}
```

- `lines`：セリフ。文字列または条件付きオブジェクト
- `choices`：選択肢、効果、タグ、遷移先
- `branch`：条件と遷移先の組み合わせ
- `ending`：エンディングID
- `when`：イベント・セリフ・選択肢を表示する条件

## 8. セーブと設定

- セーブデータは `localStorage` に保存する
- 保存キーは `lovelog.save.v1` を基本とする
- 保存対象：診断結果、選択履歴、パラメータ、既読イベント、ルートクリア状況、回収済みエンディング、設定
- JSON解析に失敗した場合は、ユーザーに状態を通知し、ゲーム専用キーのみを安全に初期化する
- 設定には文字表示速度、点滅・画面揺れを抑える設定などを用意する
- リセット操作には確認を設け、ゲーム以外のlocalStorageデータを削除しない

## 9. 画面とUI

- タイトル：はじめから、つづきから、エンディング一覧、設定
- 診断：質問、回答選択肢、進捗、結果への遷移
- AI選択：各AIの紹介と解放状態
- 育成・会話：キャラクター、親密度、不安定さ、会話ログ、選択肢
- エンディング：タイトル、本文、次の行動
- エンディング一覧：回収状況、未回収項目
- 設定：文字速度、モーション軽減、セーブ初期化

### アクセシビリティ
- 意味のある見出し、ボタンラベル、フォーカス移動を用意する
- キーボード操作に対応する
- 状態変化は必要に応じて `aria-live` で伝える
- 色だけで情報を伝えない
- モーション軽減設定を尊重する
- スマートフォン幅でも選択肢を押しやすくする

## 12. テスト・受け入れ条件

- 初回起動から診断、AI選択、イベント、エンディングまで進行できる
- AI①・AI②のクリア後にAI③が解放される
- AI③が診断と過去の選択傾向を参照する
- 選択肢の効果がパラメータ・タグに反映される
- エンディング回収状況が保存される
- 再読み込み後にセーブから復帰できる
- 壊れたセーブで画面が停止しない
- 存在しないイベントIDや条件で進行不能にならない
- キーボードだけでも主要な操作ができる
- スマートフォン幅で主要な操作が可能
- モーション軽減設定が反映される

- アカウント、クラウドセーブ、オンラインランキング

## 14. 実装上の注意

- シナリオ文とロジックを分離し、文章の変更でゲーム処理が壊れないようにする
- プレイヤー入力をHTMLとして挿入しない。表示には安全なテキストAPIを使う
- localStorageの保存形式にはバージョンを付ける
- イベントID、選択肢ID、エンディングIDの重複を避ける
- 怖さは露骨な演出より、反復・記憶・小さな違和感で積み重ねる


## 15. 初回診断フローの追加仕様

AIの人格を形成する前段階として、プレイヤー自身の性格・特性を診断するフローを設ける。流れは次の順番とする。

1. **性格・特性の簡易診断**：プレイヤーの回答から傾向を取得する
2. **MBTIタイプの選択**：診断のあと、プレイヤーが自分に近いMBTIタイプを選ぶ
3. **追加診断テスト**：MBTI選択に続けて、追加の質問に回答する
4. **結果の保存**：簡易診断結果、選択したMBTI、追加診断の回答・結果を保存する
5. **AI育成パートへ進む**：保存した結果を後続の会話やAIの人格形成に利用する

MBTIはプレイヤーが選択する項目として扱い、医学的・心理学的な確定診断としては表現しない。簡易診断と追加診断はそれぞれ独立したデータとして管理し、後から会話イベントで参照できるようにする。

### 診断データの保存項目
- 簡易診断の質問ID・回答ID・結果
- プレイヤーが選択したMBTIタイプ
- 追加診断の質問ID・回答ID・結果
- 診断フローの完了状態

## 16. AI育成パートとMDファイル連動

AI育成パートでは、用意されたMD（Markdown）ファイルを選択候補として提示し、プレイヤーが選んだ内容をAIの人格・会話に反映する。自由記述を入力する方式ではなく、制作者が用意した選択肢から選ぶ方式を基本とする。

- MDファイルは、AIごとの人格設定・記憶・会話テーマを記述するためのシナリオ素材として扱う
- プレイヤーが選択したMDファイル、選択肢ID、選択順をセーブデータに保存する
- 1つ選択するたびに、3〜5行程度の短い会話イベントを発生させる
- 会話内容は選択した設定や、すでに保存されている診断結果・過去の選択に応じて変化させる
- MDファイルの内容をゲーム内でどう読み込むかは実装時に決定する。ブラウザで直接動かす構成を維持する場合、MDファイルを事前にJavaScriptデータへ変換するか、ビルド不要で読み込める形式に整える
- MDファイルの文章をそのままHTMLとして挿入せず、安全なテキストとして表示する

### AI②：ゆきちゃんのMDファイル構成

AI②に関するMDファイルは2つ用意する。

1. **通常の人格・会話設定ファイル**
2. **前の持ち主の記録ファイル**：前の持ち主による異常な執着や愛情が含まれる内容

2つのファイルの内容がAI②の中に共存していることで、ゆきちゃんの反応に矛盾や不穏さが生じる構成とする。前の持ち主の記録は、最初からすべてを説明せず、会話イベントを通じて少しずつ表面化させる。ファイルごとの役割を明確にし、どの内容がどのセリフや分岐に影響するかを管理する。

### AI③：りりちゃんのMDファイル構成

AI③のMDファイルには、以下の情報を反映する。

- 初回の簡易診断結果
- プレイヤーが選択したMBTIタイプ
- 追加診断の結果
- AI①・AI②のルートで選んだ選択肢や行動傾向

これらの情報をもとに、りりちゃんの人格・反応・会話内容を変化させる。診断結果や選択履歴を単に説明するのではなく、りりちゃんが自分自身について語るような会話として表現し、プレイヤーとの対話のように感じられる演出を目指す。なお、外部AI APIを使用しないため、実際の自由生成ではなく、保存された情報に応じた条件分岐・セリフテンプレートで実現する。

## 17. 追加仕様の受け入れ条件

- 簡易診断、MBTI選択、追加診断の順に進行できる
- それぞれの診断結果と選択内容が保存され、再読み込み後も復元される
- 育成パートでMDファイルに対応する選択肢を選べる
- 1回の選択ごとに3〜5行程度の会話イベントが表示される
- AI②は役割の異なる2つのMDファイルを参照でき、前の持ち主の記録が会話に段階的に現れる
- AI③の会話には診断結果と過去の選択傾向が反映され、自分自身について語るような演出がある
- 外部AI APIを使わず、既定のデータと条件分岐で動作する
