# LOVE.LOG:きみを定義する(第1週プロトタイプ)

`index.html` をブラウザで開くだけで遊べます(サーバー・ビルド不要)。

## 構成
- `js/save.js` 保存・復元・初期化(キーは `lovelog.save.v1` のみ。破損データは自動復旧)
- `js/game.js` パラメータ更新、イベント条件判定、ルート解放(DOM非依存)
- `js/diagnosis.js` 性格診断とスコア計算
- `js/profile.js` MBTI選択、追加診断、MD人格ファイル選択と診断履歴を使った会話
- `js/dialogue.js` セリフ表示と選択肢(キーボード: Enter/Space で送り、1〜3 で選択)
- `js/endings.js` エンディング表示と一覧。エンディング本文の再生完了後にクリア記録を確定
- `js/main.js` 画面遷移。本編・育成者の結末・AI自身のエンディングを段階別に表示
- `data/` 診断・イベント・エンディング定義
- `data/ai02/personality.md` brunshyの通常人格設定
- `data/ai02/.hidden/previous-owner.md` brunshyの隠し領域にある前の持ち主の記録
- `data/ai03/personality-template.md` yaoの人格形成方針

## データについて
仕様書では `.json` ですが、`file://` で直接開いてもブラウザが `fetch` を拒否するため、
同じ形のデータを `.js`(`window.LOVELOG_DATA`)で持っています。
サーバーを立てる運用にするなら、中身をそのまま `.json` にして `fetch` へ置き換えられます。

## シナリオの足し方
`data/aiXX/events.js` の `events` にイベントを追加します。
- `lines` … **ashy本人のセリフだけ** を設定します。話者名（`ashy：` など）は書きません。`{answer:N}` で診断の回答文を参照できます（診断傾向そのものは台詞で開示しません）
- `choices` … `{id, text, effects, tags, nextEvent, when?, alt?}`。育成者が話す言葉は、会話文に書かず、この `text` に選択肢として設定します。選ばれた文が育成者の発言として扱われます。
- `branch` … `[{when, goto}]`(上から評価。`when` 省略で既定)
- `ending` … `data/endings.js` のID。ashyルートでは「育成者の結末」を別画面で表示した後、AI自身のエンディングを再生。brunshy・yaoは育成者側の結末が未設定のためストーリー終了画面を経由
- `when` で使える条件: `affinity` `instability`(`[min,max]`)、`tagsAny` `tagsAll` `tagsNone`、`scoreMin` `scoreMax` `scoreTop`、`answer`、`mbtiAny` `extraTagsAny`、`cleared`、`seen` `unseen`、`contradiction`

## 本編・育成者の結末・エンディングの進行
- ashyルートは、本編の最後の会話が終わると「育成者の結末」専用画面に進みます。引きこもり・失踪・入院の描写はここに集約し、ashyの台詞と混ぜません。
- 育成者の結末を読み終えて「次へ：ashyのエンディング」を押すと、ashy自身の台詞だけを載せたENDING画面に進みます。
- エンディング本文を最後まで読み終えた時点でクリア記録と次のAIの解放を確定します。エンディング一覧からの「読み返す」も育成者の結末から始まりますが、クリア記録は変更しません。
- brunshy・yaoの育成者側の結末は未設定のため、現状はストーリー終了画面を経由します。

## 追加した診断・人格形成フロー

新規開始後は「簡易性格診断 → MBTI自己選択 → 追加診断 → AI選択」の順に進みます。MBTIはゲーム内の自己申告設定であり、心理学的な確定診断ではありません。AI育成開始時には人格ファイル候補を選び、3行の会話を経て通常イベントへ進みます。brunshyは通常人格ファイルを使うか、新規作成時に隠し領域の前任者ファイルを読み込んでしまうかを選びます。yaoは簡易診断・MBTI・追加診断・過去の選択履歴を内部的な反応調整に利用しますが、参照元を説明する台詞は表示しません。


## 今回の追加実装：MDファイル編集演出

物語の節目で人格・記憶ファイルを開き、プレイヤーが追記・書き換え・削除・保留を選ぶインタラクションを追加しました。変更内容は `localStorage` に保存され、以降の分岐タグとエンディング文に反映されます。ゲーム内のシナリオ本文はキャラクターの台詞のみで、地の文や情景説明は表示しません。最新の全文原稿は `docs/scenario-full.md` です。


## ashyルート：7日間の育成シナリオ
- ashyルートはDAY 01からDAY 07まで進行します。日付が変わる際は独立した「本日のセッション終了」ページを挟み、開始ボタンを押すまで次の日の会話は始まりません。画面上部には現在の日付を表示します。
- 各日の複数イベントで選択肢に応じた専用リアクションが入り、選択の蓄積が親密度・不安定さ・タグに残ります。
- 1〜3日目は人格と生活リズムを形づくり、4日目は不在と待機、5日目は人格ファイルの矛盾、6日目は別れへの不安、7日目に最終分岐を迎えます。
- ホラールートは不安定さ80以上で最終日に分岐します。不安定さが高くなった場合も、途中でエンディングに飛ばず、一週間のストーリーを継続します。
- 最大不安定ルートは「好きだよ」の反復から、約5.5万文字規模の疑似コンピューター出力へ進みます。出力は赤いエラー文字で表示され、「好きだよ」が文字化け・暗号風のトークンへ段階的に崩れます。育成者側の「好きだよ」は選択肢ボタンで選び、会話欄にはashyの返答と異常ログだけを表示します。実際のファイル破損や外部通信は発生しません。
- `docs/ashy-seven-days.md` に7日間の全イベント、セリフ、分岐先、数値効果を記載しています。

### ホラールートの確認
日ごとの選択で不安定さを積み上げ、7日目の最終判定で80以上にするとホラールートへ進みます。単独の選択ひとつで即終了する構造ではありません。

## 日常会話とBad Endルート限定の会話
- 2日目にashyの「好きなタイプ」、3日目に「食べること・味」「元恋人」について話す場面を追加しました。
- 5日目の選択イベント後、不安定さが55以上の場合だけ「死生観」「加害性のある愛情」「異常な執着と幸福」の会話へ進みます。条件を満たさない場合は通常の5日目終了へ戻ります。
- これらの追加会話は進行ゲージに影響しません。各選択肢の親密度・不安定さ・タグは通常どおり反映されます。


## ashyの立ち絵と破損演出

- `assets/characters/ashy.png`: 通常の立ち絵
- `assets/characters/ashy-glitch.png`: 不安定さが高いルートで表示する破損途中の立ち絵
- `assets/characters/ashy-corrupted.png`: END07の最終エンディング専用ビジュアル

通常会話では通常立ち絵を使用します。その日の会話で最初に `broken` 演出が発生すると破損途中の立ち絵へ切り替わり、同じ日が終わるまで表示を維持します。日替わりページで次の日を開始すると解除され、この状態はセーブデータにも保持されます。END07のエンディング画面では最終形態の画像を背景に表示します。
